## 2. 三条硬规矩

1. **引用必须带版本 + 页码。** 写成 `CACA-CBCS 2025 精要本 · P208 表 9.5`，不写"指南认为"。跨版本冲突不合并，两个版本各自标注，以较新版本为准并说明差异。
2. **出处不等于结论。** 界面句式固定为两段并列：「指南这里写的是……（原文）」+「你的记录是……」，中间不合成"所以你应该"。指南里的处置推荐（G-CSF 一级预防、Hb≤100 用 ESA、PLT≤10 输注、LVEF 下降暂停治疗）**只能作为折叠原文**，不转成产品建议。
3. **OCR 未逐页校对。** `caca-cbcs-2025` 是 MinerU 输出，表格以 HTML 片段保留，个别数字可能串行。凡是阈值要进代码（分级表、参考线），必须先回 PDF 核对并在提交信息里写明核对了哪一页。

## 3. 版权与分发

CACA-CBCS 精要本页脚写明"版权归 CACA-CBCS 与 CMA-CSO-BO 所有"。因此：

- 本目录**仅供本地学习与开发期核对**，不随产品分发；`package.json` 的 `files` 白名单不含 `guidebooks`，`npm pack` 打出的 tgz 里没有这些文件（打包前用 `npm run pack:check` 复核）。
- 仓库保持 private。若要公开仓库或对外发布，**先移出本目录**。
- 产品界面只展示**引用元信息 + 短摘录**（≤ 200 字，带页码），不整页复制。

## 4. 更新流程

1. 新版本落地：新建子目录，文件名带年份（`caca-cbcs-2026/…`），**不覆盖旧文件**——旧引用要能复原。
2. 在 `manifest.json` 追加一条（`sha256` 用 `shasum -a 256`），并标注 `supersededBy` 的旧条目仍保留。
3. 若阈值表进代码（`dsh/ctcae.js` 之类），同步改阈值 + 单测边界 + `CHANGELOG.md` 列变化，跑 `npm run check`。
4. 引用过期的记录不改写历史，只把「指南出处」标成"该版本已被 2026 版替代"。

## 5. 与产品的关系

产品里用到的指南内容**不在本目录**，而在 `assets/reference/guideline/`（随包分发，只有页码与 ≤200 字摘录）：

| 文件 | 内容 | 对应原书 |
|---|---|---|
| `refs.json` | 指标 → 指南条目（中性粒 P227、CRA P219、CTIT P220） | 2025 精要本第 10 章 |
| `cadence.json` | 随访间隔 + 表 9.6 的 15 项检查 | 2025 精要本 9.5 / 9.6（P208–P209） |

**不要在 `guidebooks/derived/` 里放运行时数据**：这个目录不进 npm 包，装到 Desktop 会缺文件。派生数据要随包走，就放 `assets/reference/`。

指南如何进入随访节奏、指标分级、路径标签，方案与进度见 [`docs/GUIDELINE-BRIDGE.md`](../docs/GUIDELINE-BRIDGE.md)（G0–G1 已完成，G2 已落地，G3–G4 未做）。
