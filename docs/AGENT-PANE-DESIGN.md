## 2. 版式判定：本项目的特殊点（与提示词基线的关系）

本项目 D21/D34 定的是 **A 标准分栏**（`businessSide='right'`、`businessWidth=0.65`、`customFrame=false`，唯一来源 `lib/layout.js`），**不是** CustomFrame。这改变提示词两节的适用方式：

| 提示词条目 | 本项目判定 |
| --- | --- |
| CustomFrame 基线：Agent 展开默认 35%、可拖 25%–45% | **不直接适用**。split 模式下原生会话节点由宿主渲染，位置在业务区**对侧（左）**，宽度随宿主分栏合同；工作台代码里不出现第二份宽度来源。若将来实测宿主会话栏过窄挤压业务区，调整走 `businessWidth`（0.25–0.7，宿主限制）而不是自建 splitter |
| 「AI-IDE 配套设计交付」：双状态稿（工作台主区 + Agent 右栏） | **适用，但形态改为「业务区 + 左侧原生会话占位」**。状态稿仍需覆盖：默认关闭/打开、宿主会话栏窄/宽两档、加载/失败、草稿冲突；会话内容标注「宿主模拟 / 非真实 DSH 会话」 |
| 顶栏 620–760px 换行、<620px 折叠导航文字 | 归宿主 split 布局与业务区内响应式共同承担；业务区内断点一律按业务容器宽度算（与 UI-DESIGN §10 实测口径一致），不按整窗 |

> 提示词允许「项目 SPEC 决定默认值」与「明确确认后偏离」——以上判定记为本项目偏离理由，待用户确认后写入 SPEC。

## 3. 交互合同逐条落地

1. **入口**：顶栏右侧「AI 对话」按钮（图标 + 文字 + 可访问名称），状态文案四态：`未打开 / 正在连接 / 已连接·会话名 / 暂不可用`。独立收起控件；隐藏 ≠ 结束会话。split 模式下入口按钮控制的是「业务区是否请求宿主显示会话节点」，状态来自宿主回执，**不由工作台自证**。
2. **会话创建**：用户首次显式点击才创建/复用；不加载时静默新建；并发与慢返回不重复创建；所有权未知不发送。会话归属用 `owner/repo` 身份（`lib/identity.js`），repository 改名影响归属——发布后不改仓库地址。
3. **上下文衔接（本项目重点）**：从四类页面提供「与 Agent 讨论」，生成**可预览草稿**（标来源/时间/核对状态/缺项）：
   - 一图秀：当前指标序列 + 换方法断线说明（含「不可比」标注）；
   - 就诊准备：问题清单 + 待办（已是用户确认项，可直接引用）；
   - 草稿核对：仅**已接受**的事实，不含未核对候选（候选进草稿 = 替 AI 背书未核实数据，禁止）；
   - 我的关注：研究线索空态时不提供入口。
4. **带入对话**：草稿填入**原生会话输入框**。⚠️ split 模式下业务区在 iframe 里，向宿主原生输入框写草稿**需要宿主 API**——当前合同未给出该方法名，**不猜名调用**；拿不到就把草稿做「复制到剪贴板」回退，绝不自建聊天框。
5. **草稿冲突**：原生输入框已有内容时，提供复制/追加/取消三选，保留用户已有输入。
6. **AI 输出边界（与既有红线一致）**：AI 回复只在原生界面展示；不写回 `observation`/`record`；`viewpoint.is_conclusion` 恒 0 的合同不因 AI 改变；接受 ≠ 审核（`reviewed_by` 保持 NULL）。
7. **私密边界（与 D39 fail-closed 一致）**：私密心理/性健康/生育记录**默认不进上下文草稿**，逐项显式勾选才带；带私密项的草稿在预览中标红提示「将发送到宿主会话」。

## 4. 数据模型解耦

| 数据 | 归属 | 存储 |
| --- | --- | --- |
| 面板展开/宽度等展示偏好 | 工作台 UI | `workspace.settings_json`（复用 demo 标记同款机制），清数据即清偏好 |
| 会话归属 / 会话 ID | 宿主绑定 | 不落库；不作为患者病情事实 |
| 一次性上下文草稿 | 会话期 | 默认不持久化完整草稿；只存「最近一次带入摘要」供撤回提示 |
| AI 产生的一切内容 | 原生会话 | 工作台零持久化 |

- [ ] 四类来源页的草稿预览含来源/时间/核对状态/缺项；未核对候选不出现。
- [ ] 私密项默认不在草稿；显式勾选后有发送前红色提示。

- [ ] **V2 实机**：在目标 Desktop RC 里真实渲染原生会话、可输入、可回复；静态 DOM 与开发自测不算验收。
