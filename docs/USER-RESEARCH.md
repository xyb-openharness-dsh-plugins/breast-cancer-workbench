## 患者与照护者研究计划

对齐首要结果后，检索患者体验/未满足需求研究、照护者研究、患者组织与当地支持资源；再核对医学资料的适用范围。临床流程不直接作为患者导航。

每条证据记录：URL/机构、发布或更新日、获取日、地区、人群及阶段、方法/样本、主要发现、局限、可支持的需求假设及待验证问题。

分析结构：触发情境 → 实际困难 → 当前应对 → 时间/体力/情绪负担 → 期望结果 → 需求假设 → 验证方式。

特别待研究：低负担记录、患者与家属分工、报告理解、治疗期生活影响、营养与心理需要、身体形象/上肢功能、生育和性健康、信息分享选择。是否纳入功能以证据与用户讨论为准。

真实访谈与可用性验证均未开展；不以桌面研究替代。

## 从证据到任务假设

| 假设 | 依据 | 候选任务/功能 | 待验证与验收方向 |
| --- | --- | --- | --- |
| N1 一次带材料就能开始，减少重复组织病史 | 双参考设计＋E04信息需求，具体输入负担仍是假设 | S2；资料→草稿→问题→摘要 | 让患者拿真实任务走查，能否找到出处、少量操作得到有用摘要 |
| N2 临床、营养、心理帮助持续进入复诊沟通 | E02/E04＋社区设计框架；营养专门需求仍缺原始研究 | S3/S5；少量记录、解释、问题回顾 | 哪些内容值得记录，哪些造成负担；不要设日记完成率目标 |
| N3 恢复与长期生活需要在架构中有位置 | E02患者教育背景 | S4；身体变化、生活困扰、专业建议回顾 | 患者如何命名这些任务，是否放全程管理二级即可 |
| N4 家属既代办也有自己的支持需要 | E01照护者研究 | S7；主体/操作者分开、自己的支持记录 | 谁实际用桌面端，患者与代办者分享意愿冲突如何处理 |
| N5 不同来源/标本的病理信息需可回溯 | E03医学背景＋领域建模假设 | S2/S6；病理档案、来源与版本 | 由专业人员核对字段语义，再用病理样本验证解析/展示 |

证据与产品追踪：E/N → 本表 → SCENARIOS的S编号 → SPEC模块 → 后续功能ID/数据与验收。当前没有用发生频率或收益打分冒充真实量化研究。

## 仍需补充
