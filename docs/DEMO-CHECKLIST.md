日期：2026-10-17。状态：待用户逐项签认。上位文档：[SPEC](SPEC.md) §0 三道闸口。

**这份表是 G2 的判定依据。** G2 没有"整体看着不错"这一档：34 个页面/子页逐页签，七大组逐项签，任一项未签即 G2 未通过，不得开始写业务代码。

判定符号：`通过` / `不通过` / `不适用（写明理由）` / `未验证（写明缺什么）`。**"未验证"不等于"通过"。**

## 1. 功能完整与可用

### G2-1.1 一图秀：多指标选择

| 检查点 | 怎么操作 | 通过标准 |
| --- | --- | --- |
| 指标池完整 | 打开 `#timeline` → 指标检测列表 | 16 项全部可见，分「检验 / 影像与功能 / 康复测量」三组，不靠滚动猜 |
| 多选上限 | 连续勾选第 5 个 | 第 5 个被拒并给出可读提示，不是静默失败；已选 4 个仍可用 |
| 单序列退化为 1 | 全部取消只留 1 个 | 图表仍正常，纵轴按该指标自身范围缩放，不报错、不留空白画布 |
| 全取消空态 | 取消全部 | 显示空态文案 + "恢复默认（CA15-3 / 白细胞 / 臂围差）"按钮，不是一片白 |
| 指标→颜色稳定 | 勾选 A 后取消，再勾选 A | 同一指标两次颜色一致；且与指标卡左侧色条同色（线色同源） |
| 单位不同不共轴 | 同时选 CA15-3（U/mL）与 臂围差（cm） | 按各自 min/max 归一化，**不得**提示"单位不一致无法绘制"就罢工 |
| 选择状态可持久 | 换到别页再回一图秀 | 已选指标不丢（本页内）；刷新后回默认，且原型条已写明"刷新重置" |

### G2-1.2 一图秀：动态更新

| 检查点 | 怎么操作 | 通过标准 |
| --- | --- | --- |
| 时间窗切换 | 3 月 / 6 月 / 12 月 / 全期 | 4 档都即时重绘；窗内无数据点时给"该时段无记录"而非空图 |
| 缩放 | 拖 40%–100% | 图形与刻度同比缩放，标签不重叠、不溢出画布 |
| 治疗条联动 | 关/开"治疗"开关 | 治疗条独立于数据区，不与曲线重叠；关掉后数据区不留空洞 |
| 关键点 | 关/开"关键点" | 只在末点标值；两个序列末点相近时上下错位，不叠字 |
| 变化标注 | 关/开"变化" | 检验用 `%`，康复测量用绝对值带单位（如 `+0.6cm`），**不得**对 cm 算百分比 |
| 悬停 | 鼠标划过曲线 | 出现 tooltip：指标名 + 日期 + 值 + 来源；离开即消失 |
| 点选固定 | 点一个数据点 | 固定详情卡，显示该点来源文档；再点取消；固定状态不因重绘丢失 |
| 范围→看板一致 | 切时间窗后回看板 | 看板"最近变化"不因一图秀的时间窗改变而变（看板有独立口径） |

### G2-1.3 图表引擎效果（ECharts 等效）

**现状：原型是手写 SVG，未引入 ECharts。** 这一组按"用户可感知的图表能力"判，不按库名判。

| 检查点 | 通过标准 |
| --- | --- |
| 多序列同图 | 最多 4 条，颜色/图例/顺序稳定 |
| 折线平滑 | 平滑曲线经过真实数据点，不是过冲失真的样条 |
| 数据点可见 | 每个点有圆点，末点加重；点大小随屏宽不塌缩 |
| 图例可交互 | 点图例可单独隐藏/显示该序列（或明确说明本版不支持并说明替代） |
| 空态/断线 | 缺测区间断线并标注，不用直线硬连 |
| 缩放与重绘 | 容器宽度变化后重绘不错位（1180 / 900 / 390 三档截图） |
| 导出可用 | 图表可被截图或导出（一期只要求 Markdown 内嵌，图表导出为二期） |

**待定 D26**：一图秀最终用手写 SVG 还是本地 vendor 的 ECharts。
- 选 A（手写 SVG）：包体小、离线稳，但图例联动/缩放要自己写，维护成本在本项目。
- 选 B（ECharts 本地 vendor）：能力齐，但要在 `file://` 与 DSH 容器内都验证离线加载，且包体 +约 1 MB。
- **未定之前，G2-1.3 只能按"等效能力"判，不能声明"已用 ECharts"。**

## 2. UX 细节

### G2-2.1 多指标列表

| 检查点 | 通过标准 |
| --- | --- |
| 每项信息 | 名称 + 最新值 + 单位 + 较前次变化 + 来源日期，五项齐全 |
| 排序 | 按分类分组，组内按最近记录时间倒序；不按字母序 |
| 长列表 | >900px 时列表在 300px 区域内独立滚动，底部有渐隐提示；窄屏折叠为 `<details>` |
| 无数据项 | 显示"未记录"与"去记一次"，不显示 0、不显示空折线 |
| 状态标记 | 超出参考范围只标"值得问"，不出现"异常/危险"等诊断性措辞 |

### G2-2.2 指标卡翻转

| 检查点 | 通过标准 |
| --- | --- |
| 真 3D 翻转 | 沿 Y 轴旋转 180°，**不是**上下展开、不是淡入替换 |
| 布局不跳 | 翻转前后卡片 `rect` 完全一致（x/y/w/h 四项相同） |
| 背面不透明 | 背面文字不透出正面内容，无重影 |
| 单卡独立 | 连翻 3 张，各自状态独立；翻第 2 张不影响第 1 张 |
| 连续翻转稳定 | 同一张连翻 10 次不位移、不叠字、不复位 |
| 键盘可达 | Tab 到卡片，Enter/Space 翻转，`aria-pressed` 同步 true/false |
| 减少动效 | `prefers-reduced-motion` 下过渡≈0，但翻转结果仍生效 |
| 内容边界 | 背面不出现诊断结论、不建议停药/换药，只给"这是什么 / 怎么读 / 该问什么" |

### G2-2.3 Logo 与视觉一致性

| 检查点 | 通过标准 |
| --- | --- |
| 比例 | Logo 原始比例不变形，`object-fit:contain`，不裁切 |
| 完整性 | 不做圆形裁切、不叠色块、不加投影 |
| 位置 | 侧栏品牌区固定位，滚动不跟随位移 |
| 色系 | UI 主色与 Logo 同族（柔粉/莓红），不出现第二套主色 |
| 暗色/灰度 | 灰度打印下 Logo 与文字仍可辨（截图验证） |
| 空图处理 | Logo 加载失败有 alt 文本兜底，不出现破图图标（实现为隐藏图片 + 文字圆标） |
| 资源可达 | 引用路径都在原型目录内（`assets/brand/...`）；`file://` 与 HTTP 两种方式打开 `naturalWidth > 0`。**跨目录 `../../assets/` 判不通过**——预览服务会把它规范化到根外并 404 |
| 尺寸与体积 | 48×48 显示用 96/192 的图，页面不加载 1920 原图（298 KB）；`srcset` 提供 2x |
| 同源 | 侧栏图标与「关于」弹窗的完整竖版来自同一套资产，不混用截图或 emoji |

### G2-2.5 版本号（v0.3.0 新增）

| 检查点 | 通过标准 |
| --- | --- |
| 三处一致 | 顶栏 chip、页脚、关于弹窗显示同一个 `vX.Y.Z`，与仓库根 `VERSION` 逐字相同 |
| 页脚常驻 | 390 宽下顶栏 chip 可以隐藏，页脚版本号必须可见且不换行错位 |
| 可追溯 | 点顶栏 chip 打开「关于」，能看到版本、构建日期、版本来源、渠道标签四项 |
| 不手写第二份 | 代码里只有 `APP_INFO.version` 一处数字；`node scripts/check-version.mjs` 全绿 |
| 文案 | 不出现"设计草案 v0.3"代替版本号；描述可有，但必须另有 `vX.Y.Z` |

### G2-2.4 其它 UX 细节（逐条打勾）

- 焦点可见：所有可交互元素有 focus ring，不与 hover 混同。
- 点击目标：≥40×40px（移动端），相邻按钮间距 ≥8px。
- 危险动作二次确认：删除记录、覆盖草稿、清空问题清单。
- 反馈：每次保存/导出都有 toast，且文案说清"只是本页演示"还是"已保存"。
- 文案：不出现"系统判断""建议治疗"，一律"记录/整理/可询问"。
- 数字格式：小数位与指标定义一致（臂围 1 位、LVEF 0 位、T 值 1 位），末尾零不丢（`1.20` 不能显示成 `1.2`）。

## 4. 首页（顶栏）两个状态按钮

顶栏右侧两个**状态型入口**，反映「工作台就绪」的两步：业务数据没放好，对话就进不去。它们**不是**业务统计（不是资料进度、不是关注阶段）。

| 编号 | 按钮 | 显示（有值） | 显示（空态） | 点击行为 | 状态源 |
| --- | --- | --- | --- | --- | --- |
| G2-4.1 | **资料目录** | `资料目录 已激活` + 粉点，`title` 给绝对路径 | `资料目录 未设置` + 灰点 | 已配置 → 设置弹窗「工作区」tab；未配置 → 直接开目录选择器 | `cfg.root` 是否为空 |
| G2-4.2 | **对话** | `对话 进行中` + 粉点 | `对话 未进入激活` + 灰点 | 已进入 → 看会话归属与状态；未进入 → 创建/恢复本工作台会话 | `state.session` 是否存在 |

当前 v0.3 的初始态就是用户指出的那一组：**资料目录已激活，对话未进入激活**。

判定细节（逐条验，缺一条不算过）：

| # | 检查点 | 通过标准 |
| --- | --- | --- |
| 4-a | 状态与状态源一致 | 改目录 / 建会话后按钮文案与点色立刻跟着变，不是写死的静态标签 |
| 4-b | 依赖顺序 | 目录未设置时点「对话」→ **先要求选目录**，不能直接建会话；文案要写清"不会在默认位置、主目录、当前仓库静默新建文件夹"（workbench-standard §6） |
| 4-c | 目录校验 | 选 `/`、用户主目录、桌面根 → 被拒并给可读原因；拒绝后**留在选择器**，不是静默失败 |
| 4-d | 选完目录 | 状态转「已激活」，toast 明确指向下一步（开始对话），并落到设置弹窗的工作区页 |
| 4-e | 创建会话 | 显示会话归属目录 + 开场草稿，明写**不会自动发送**；关闭后状态转「进行中」 |
| 4-f | 开场草稿随阶段 | DEMO-2（刚确诊）的草稿不能是"术后上肢/臂围"，每阶段一句 |
| 4-g | 会话归属单档案 | 切换演示画像后回到「未进入激活」，不沿用上一个档案的会话 |
| 4-h | 取消无残留 | 取消目录选择不产生空目录、空项目、工作区、会话或绑定 |
| 4-i | 不阻断业务 | 目录未设置 + 对话未激活时，看板、指标卡翻转、一图秀仍全部可用；只在依赖会话的动作处引导 |
| 4-j | 窄屏可辨识 | 390 宽**不得**用 `display:none` 藏掉这两个入口；字号可缩到 10.5px，但「资料目录」「对话」两个标签必须看得见（曾实测被 900 断点整块隐藏，已修） |
| 4-k | 不与业务状态混用 | 「资料整理进度」不再是顶栏状态（写进「资料很多，帮我理清楚」入口副标题）；「当前关注阶段」改为页头按钮。旧装饰标签「模拟资料目录 / 会话未接入」已删除 |
| 4-l | 演示画像一致 | DEMO-2（资料极少）首页进度给"还没有资料 · 先导入一份"，不得沿用 DEMO-1 的 `4 / 5` |

## 5. Schema 设计与 Demo 数据

### G2-5.1 Schema 可用性

| 检查点 | 通过标准 |
| --- | --- |
| 能建表 | [SCHEMA-SPEC](SCHEMA-SPEC.md) 的 DDL 在空库执行成功（已实测 25 表 / 26 索引） |
| 约束真生效 | `viewpoint.is_conclusion=1` 被拒；非法 role 被拒（已实测） |
| 派生不落库 | 臂围差值、变化率、BMI 均无对应列；只在读取时算 |
| 更正不覆盖 | `supersedes_id` 链存在，旧值保留并标 `superseded` |

| 页面状态不入库 | 展开/翻转/选中/时间窗等界面状态在 schema 中查不到 |
| 迁移可执行 | 空库与旧库各跑一次；失败有回滚说明 |

### G2-5.2 Demo 数据：至少 5 套画像

**5 套不是 5 份随机数据，是 5 个必须覆盖的边界画像。** 每套都要能独立切换、独立清空。

| 编号 | 画像 | 侧别/术式 | 阶段 | 必须覆盖的边界 |
| --- | --- | --- | --- | --- |
| DEMO-1 | 全程完整（当前原型林女士） | 左 / 改良根治 + 腋窝清扫 | 内分泌治疗 | 4 次臂围测量、8 周期化疗、放疗、16 项指标齐全 |
| DEMO-2 | 新确诊、资料极少 | 右 / 未手术 | 刚确诊 | **空态为主**：无治疗、无测量、指标仅 1 次；首页进度显示"还没有资料 · 先导入一份"，且资料目录为"未设置"（演示未就绪链路） |
| DEMO-3 | 保乳 + 前哨淋巴结 | 右 / 保乳 + SLNB | 放疗期间 | 无腋窝清扫 → 臂围差长期 0.2–0.4；放疗野不同 |
| DEMO-4 | 双侧 + 复发 | 双侧 / 两次手术 | 复发后治疗 | 侧别歧义、两次手术时间轴叠加、指标断线 |
| DEMO-5 | 数据冲突 / 待核对 | 左 / 根治 | 随访 | 同一指标两法不同值、一条更正记录、一份文档 `待核对` |

每套数据的硬要求：

- 全部带 `[UI DEMO]` / "模拟"标记，界面与导出都不能被误认为真实病历。
- 清理只删 manifest 登记的 demo ID，不按"看起来像 demo"判断。
- 每套含至少 1 个**故意留空**的字段，用来验空态（不留空的 demo 验不出空态 bug）。
- DEMO-5 必须能复现"A14 更正传播"：改一条测量 → 看板/一图秀/表格三处同步，旧导出标"已过时"。
- 数据量：单套 ≥120 条测量/观测，用于验列表滚动与图表重绘性能（不要求压测，要求不卡）。

## 6. 从 xyb 开发日志提炼的"重复修改"清单

以下 6 条是 xyb 项目**实测出过并修过**的真缺陷，不是设想。本项目在 G2 逐条自查，避免重复踩。

| 编号 | xyb 的真实缺陷 | 本项目的检查动作 |
| --- | --- | --- |
| R1 | 详情函数 `careDetail(id)` 定义了但从未被调用，新加字段全不显示 | 对每个"详情/展开"入口，断言 DOM 里真的出现新字段，不能只看函数存在 |
| R2 | 同一个 class（`.tl-swatch`）被图例和色块复用，测试选错元素→误报 | 选择器按 `data-testid` 唯一化；图例与色块用不同 class |
| R3 | 详情页图标颜色写死灰色，与列表状态色不一致 | 状态色通过父容器类 + `currentColor` 传递，不写死 |
| R4 | 指南数值 `1.2–2.0 g/kg` 被显示成 `1.2–2`（末尾零丢失） | 医学数值一律 `toFixed(固定位)`；对每个数值型指标断言小数位 |
| R5 | 一级 Tab 缺 `overflow-x:auto`，窄容器被压扁而非滚动 | 1180/900/390 三档逐页截图；Tab 必须可滚不被压缩 |
| R6 | 420px 下仍两列（容器查询顺序被更大断点覆盖） | 断点用 `min-width` 升序书写并实测；不靠阅读 CSS 推断 |

另 6 条来自 xyb 的"常见坑"，同样纳入：

| 编号 | 坑 | 检查动作 |
| --- | --- | --- |
| R7 | 改了代码但界面是旧的 | 每次验收记录文件 SHA-256 与版本号，截图与 hash 同批 |
| R8 | 装错 profile → 安装成功但左侧无入口 | 装机后 `grep <包名> ~/.dsh/profiles/<p>/package.json` 必须同时出现在 dependencies 与 bundles |
| R9 | 翻转卡以索引共享状态 / 背面占位撑高 | 每卡稳定 ID；正反面绝对定位同一容器；连翻多张验证 |
| R10 | 图表 viewBox 与容器纵横比不匹配 → 挤压变形 | 三档宽度 + 大字号（放大 150%）分别截图 |
| R11 | Token 写进包、日志或终端输出 | 打包后 `tar -tzf` + 全仓 grep 假值校验；日志不打印请求头 |
| R12 | 只按大 Tab 实现，漏二级页/弹窗/折叠区 | 先出"原型功能树"，逐页差异表；二级页与设置窗计入 G2 |

### 6.1 交接纪律（来自 HANDOFF 模板）

开发阶段每次交接只写**短交接**，不复述历史长文；缺任何一项都算交接失败：

1. 版本 / 分支 / 工作区状态（是否干净、有无未提交改动）
2. 已完成的功能 ID 与**证据**（截图、断言输出、哈希）
3. 当前错误与**最短复现步骤**
4. 未验证的 Desktop / 外部服务 / 跨平台项（明写"未验证"，不写成"应该没问题"）
5. 用户已确认的偏好与授权范围（哪些能改、哪些要再问）
6. 下一步的具体文件与命令
7. 新踩的坑先记 INCIDENT，稳定后提炼成 LESSONS，并写明适用边界

配套要求：任何"已修好"必须同时给**改前症状 + 根因 + 改后断言**三样；只有"改好了"不算证据。本项目当前短交接见 [HANDOFF](HANDOFF.md)。
