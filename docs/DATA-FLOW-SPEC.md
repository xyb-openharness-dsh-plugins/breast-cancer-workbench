# 小粉宝工作台 · 数据流与更新语义 DATA-FLOW-SPEC v0.1

日期：2026-10-17。状态：**草案，待 G3 评审**。
体例参照 `xyb-workbench/docs/design/DATA-FLOW-SPEC.md`；本项目增加"看法=信息"与"测量协议"两条专属链路。

上级文档：[SPEC v0.4 §6](SPEC.md) · [SCHEMA-SPEC](SCHEMA-SPEC.md)（表与约束）。

---

## 1. 直接回答

**会更新，但不是"推送"式更新，而是"读取时实时计算"。**

工作台没有"录入后触发看板刷新"这个动作，因为看板、一图秀、指标卡都**不保存自己的副本**。用户记一条臂围，看板下次渲染时自然就变了——中间没有任何同步步骤。

好处：不会出现"看板说 1.8cm、指标页说 1.1cm"。只有一个来源，就不存在两个版本。

**例外只有一类：结论型产物**（摘要、导出、问题清单、AI 回复）。它们**不静默重算**，而是标"已过时"——理由见 §3、§6。

## 2. 主链路

```
① 导入原件
   document(sha256 去重) → 原件落盘，状态 stored
        ↓
② 解析（可失败）
   parse_job queued → running → succeeded / failed
   失败：原件仍在，可重试或手工录入；不产生 record
        ↓
③ 生成候选（带出处）
   candidate(field, value, unit, method, page_ref, bbox)
   状态 pending；同一文档同字段去重（UNIQUE document_id+field+value_text）
        ↓
④ 用户逐项核对
   accepted / edited / rejected / needs_review
   ★ 接受只表示"录入"，不等于临床审核
        ↓
⑤ 写入事实层
   record(occurred_on, source_kind, source_document_id)
   + observation / measurement / biomarker / treatment_event
   + source_ref（原文位置）
        ↓
⑥ 读取时实时派生（不落库）
   臂围差最大值、较前次变化、趋势、BMI、提醒文案
        ↓
⑦ 各页读模型
   看板 / 一图秀 / 指标卡 / 上肢页 / 就诊准备
        ↓
⑧ 生成结论型产物（快照）
   摘要 saved_result / 导出 export_job / 问题清单
        ↓
⑨ 来源变更 → 快照标 stale，不自动重写
```

**⑤ 和 ⑦ 之间没有"同步"这一步**，这是刻意的：少一层同步就少一类不一致缺陷。

## 3. 三类更新语义

| 类型 | 例子 | 语义 | 为什么 |
| --- | --- | --- | --- |
| **事实型** | 化验值、臂围、引流量、体重、体温 | 写入即生效；读取时实时计算 | 客观数据，变了就是变了，不需要用户再确认 |
| **派生型** | 臂围差值、较前次变化、BMI、趋势线、"最近一次" | **默认不落库**，读取时算；口径写在 §4。唯一例外：`measurement.derived_diff_num` 在写入时固化，因为配对关系与协议在那一刻确定，事后规则改了不该改历史 | 存了就会和源数据不同步；但写死的配对差值属于"当时的事实" |
| **结论型** | 摘要、导出、问题清单、AI 生成内容 | **不静默重算**；源变更后置 `stale_at` + 原因，保留旧快照 | 结论会影响用户对病情的理解，静默改会让用户以为"一直如此"，也无法回溯 |

### 3.1 哪些录入会触发"结论型过时"

| 录入 | 看板/一图秀 | 摘要与导出 |
| --- | --- | --- |
| 新增化验值、臂围、引流量、体重 | ✅ 实时更新 | ⚠️ 标"摘要生成于 X 日，此后有新记录" |
| 新增症状强度 | ✅ 实时更新（轨道） | ⚠️ 同上 |
| 新增"看法/担心" | ✅ 只在看法区出现 | ⚠️ 同上，且带"用户自述" |
| **更正**旧记录 | ✅ 取新版本 | ⚠️ 标"其中一条已被更正，建议重新生成" |
| 撤回一条看法 | ✅ 从看法区消失 | ⚠️ 导出中该条标"已撤回"或按用户选择移除 |
| 修改测量协议 | ✅ 旧序列断线 | ⚠️ 标"测量方法变更，前后不可比" |

## 4. 派生口径（必须唯一，禁止各页各算）

### 4.1 臂围差值

```
单点位差值 = 患侧 value_num − 健侧 paired_value_num        （同一 set、同一 point）
              → 写入时算一次，存 measurement.derived_diff_num
一次测量最大差 = max(四个点位 derived_diff_num)             → 读取时算，不落库
趋势图与看板展示值 = 最近一次 set 的最大差
```

约束：`paired_value_num IS NULL` 时不生成差值，界面显示"未成对测量，无法比较"；不拿别的日期补齐。

为什么单点差值要存、最大差不算：配对差值是"这一次测量的事实"，协议与配对在写入时确定；最大差是"按当前口径的派生视图"，口径（例如改成取前三高均值）一变就该跟着变，不该改历史行。

### 4.2 较前次变化

```
检验类（LAB_METHOD 可比）：百分比 = (本次 − 前次) / |前次| × 100%，保留整数
测量类（协议可比）：绝对值 = 本次 − 前次，带单位（如 +0.7 cm）
不可比（方法/协议不同）：不显示变化值，显示"方法已变更"
```
方向只给箭头，不做好坏着色（见 UI-DESIGN 色彩规则）。

### 4.3 可比性判定

| 条件 | 结果 |
| --- | --- |
| 同 `metric_code` + 同 `metric_version` + 同 `unit` + 同 `lab_method` | 连线 |
| 同 `metric_code` 但 `lab_method` 不同 | 断线，图例标"方法不同" |
| `measurement` 同 `metric_code` 但 `protocol_id` 不同 | 断线，标"测量协议变更" |
| 单点 | 只画点，不连线，提示"再有一次记录后可看趋势" |

### 4.4 "值得讨论"提醒（看板与上肢页）

```
if 最近一次臂围最大差 ≥ 2.0 cm          → 提示"已到达 2cm 参考关注线，建议和治疗团队讨论"
else if 较前次增加 ≥ 0.5 cm              → 提示"本次较上次增加 0.7cm，可一并说明"
else                                     → 不提示
```
**输出只能是一句"值得和医生讨论"，不能出现"疑似水肿/提示复发/建议治疗"。** 阈值 2cm 是**提示口径，不是诊断标准**，界面必须带"具体口径待专业确认"。

### 4.5 空值与三态

- 没有记录 → 不显示数值，显示空态与"记一次"入口；
- `not_tested` → "未检测"（明确说没做）；
- `unknown` → "未记录"（不知道做没做）；
- 三者不可合并成"阴性"或"正常"。

## 5. 更正传播

```
用户更正一条测量
  → 新建 record(version+1, supersedes_id=旧记录)
  → 旧 record: status='superseded'
  → 新 measurement 指向新 record；旧 measurement 保留
  → 读取时只取"未被取代的最新版本"
  → 依赖旧值的 saved_result / export_job 置 stale_at + stale_reason
  → 界面：详情卡显示"此点已更正（10-14 15:20），查看新值"
```

三条禁止：不 UPDATE 覆盖旧值；不删除旧行；不在界面静默替换而不提示。

## 6. 导出与快照

| 步骤 | 规则 |
| --- | --- |
| 取材范围 | 只取用户勾选项（`export_job.scope_json`）；私密项默认不勾选 |
| 分区 | 事实 / 派生 / **我的看法与担心（不是医生结论）** / 想问题目 |
| 版本 | 记录生成时间与数据截止时间；两者不同必须分开写 |
| 过时 | 生成后源数据变更 → 该导出标"已过时"，不自动重写文件 |
| 撤回 | 看法被撤回后，重新导出不再包含；旧文件保留但标过时 |
| 格式 | 一期只有 Markdown 通过验收；PDF/JPEG/HTML/DOCX 需逐格式单独验收 |

## 7. 私密与分享过滤点

私密内容（心理、性健康、生育、遗传）在**三个位置**过滤，缺一处就会泄漏：

1. **读模型**：一图秀、看板、摘要的查询默认排除 `is_private=1`；
2. **导出**：不勾选即不出现，勾选时单独提示"将包含私密内容"；
3. **Agent 预览**：预览面板列出将发送的条目数与类别，私密项默认不发送，逐次确认。

## 8. AI 数据边界（一期只整理）

| 允许 | 禁止 |
| --- | --- |
| 读事实区与派生区，生成"问题草稿""时间线摘要" | 读 `viewpoint` 后当成事实陈述 |
| 引用时注明来源记录与日期 | 输出诊断、分级、预后判断 |
| 标注"以下为整理结果，需你核对后使用" | 未经用户确认直接写入 `record` |

引用看法时必须带"用户自述，非医生结论"；AI 产物写入 `saved_result(kind='agent_reply')`，同样受 §3 结论型语义约束。

## 9. 失败态与幂等

| 情形 | 行为 |
| --- | --- |
| 解析失败 | `parse_job.status='failed'` + 错误原因；原件保留；可重试；不产生候选 |
| 重复导入同一文件 | `sha256` 命中 → 提示"已存在（导入于 X 日）"，不重复建文档 |
| 候选字段重复 | 同文档同字段同值 `UNIQUE` 命中 → 合并，不产生两条 |
| 断网/中断 | 解析任务 queued 保留，下次启动继续；写入用事务，半条不落库 |
| 时钟不一致 | `occurred_on`（医疗事件日期）与 `recorded_at`（录入时刻）分开存，界面只显示前者 |

| ~~候选与原件缺"医疗事件日期"字段~~ **已解决** | 2026-10-17 用户确认「ok」后新增 `0002_candidate_dates.sql`：`document.report_date`（原件上的报告/采样日期）与 `candidate.occurred_on`（该条候选所属医疗事件），**均可空、不回填**。取值优先级：候选自带 > 本次传入 > 材料报告日期；三者都没有就报 `date_missing`/`DATE_REQUIRED`，**不拿 `imported_at` 顶替**。见 [MINERU](MINERU.md) §4 |
| 解析引擎的识别准确率 | 已用 1 页合成 PDF 跑通全链路（[MINERU](MINERU.md) §6）；真实报告的错读率、双栏排版、扫描件 OCR 仍未验证，不做承诺 |
