# 需求起点

## 用户明确要求

- 服务乳腺癌患者及照护者。
- 开发 DSH Desktop 配套工作台。
- 参考 xyb-workbench，使用社区 xyb-workbench-starter。
- 开始构建目录、调研需求，与用户互动确认 SPEC。
- 2026-10-17 用户明确指定本机 Downloads 下的 xyb-workbench-starter。
- 2026-10-17 用户选择候选3：全病程管理，并要求同时参考 xyb-workbench 与 ovarian-workbench 的功能架构。

## 待确认

全病程中各阶段的任务深度与完整步骤、成功结果、主要操作者、服务地区及病理人群范围、AI 价值和数据分享方式、一期/二期、布局、产品名称与包/仓库身份。

## 选择记录

1. 就诊准备：导入报告 → 核对信息 → 回顾病程 → 形成就诊摘要和提问清单。
2. 治疗期照护：记录既定安排与不适 → 整理待办 → 回顾变化 → 准备下次沟通。
3. 全病程（用户已选择）：按当前阶段组合以上任务；具体覆盖和信息负担待细化。

此处不确定页面树，不据候选场景宣称研究已验证。

功能架构候选见 [SPEC](SPEC.md)，参考能力与改造理由见 [FEATURE-REVIEW](FEATURE-REVIEW.md)。用户选择全病程，不等于已确认这些页面、所有特殊人群或全部一期交付。

## 新增用户要求

2026-10-17：数据模型谨慎设计，支持前端与业务流程演进；先HTML交互工作台UI，经用户确认后才开发；两项同步社区脚手架。用户提供小粉宝Logo，保存assets并作为UI色系基准。

## 对 v0.1 原型的反馈（2026-10-17，用户原话要点）

1. **乳腺癌特定场景基本没覆盖**——点名术后康复、淋巴水肿护理。
2. **一图秀的动态图比 xyb-workbench 简陋**——没有动态，没有多指标列表。
3. **所有指标卡片的动态不对**——"反转变成了上下显示"。

三条都不是审美问题，是能力与实现问题。证据、根因与修复清单见 [GAP-ANALYSIS](GAP-ANALYSIS.md)。据此：
- 场景层：新增 S8/S9/S10（患肢沉重与四点位测量、内分泌治疗副作用、术后带管引流），"全程管理"改名"全程与康复"并新增两个二级。
- 交互层：一图秀重做为 16 指标有状态回顾界面（多选 ≤4、3/6/12 月与缩放、治疗条、悬停与点详情）。
- 实现层：指标卡改为固定高度的真 3D 翻转，单卡独立状态，不整页重渲染。

v0.2 已交付待查看；用户确认的是**范围与交互**，不是像素。范围未确认前不开业务代码。
