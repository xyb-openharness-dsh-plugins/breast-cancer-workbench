## 3. 一图秀交互规格（核心）

> 通用开发规范见脚手架 `docs/16-ONE-CHART-SPEC.md`（R1–R12 硬规则、C1–C12 断言）。**本项目 v0.3 是该规范的参考实现来源**；本节记录本项目的具体口径，与规范冲突时以规范为准并记录偏离。

### 3.1 布局

```
[ 筛选栏 238px ] [ 图表卡 + 症状轨道 ]
                   [ 指标卡片（按 6 类分组） ]
                   [ 治疗时间线列表 ]
```

筛选栏 sticky；指标列表 300px 内滚动并做底部渐隐；≤900px 时"选择指标"折叠为 `<details>`，默认收起。

### 3.2 状态

```js
{ range:'3m'|'6m'|'12m'|'all', zoom:40–100,
  sel:[code] (≤4), toggles:{treatment,keypoints,changes},
  pin:{code,date}|null, flipped:Set<code> }
```

选择变化只重绘 `#chart-panel`，不重渲染整页（避免丢失焦点与翻转状态）。

### 3.3 图表

- 多序列，每条线按**该指标全部记录**的 min/max 归一化；图例写明"全期 12.1–18.4"与"不代表数值可比"。
- **治疗条与数据区分离**：顶部 4 行治疗条（手术菱形、化疗/放疗/内分泌色条），不再用半透明色带压住曲线；关闭"治疗节点"后治疗条与手术虚线消失，数据点位置不变。
- 时间轴按所选范围生成月刻度；缩放滑杆控制窗口占比，右端锚定最新日期。
- 悬停显示最近点提示（指标/值/单位/日期/来源）；点击固定为详情卡，可回原文。
- "关键点数值"只标每条线最后一个点，按序列奇偶错开 13px，避免多条线末端重叠。
- "变化 ≥20%"：检验类显示百分比；康复测量显示绝对变化（如 `+0.7cm`），避免 0.5→1.1 被写成 +120%。
- 单点不连线；窗口内无点显示空态而不是空白坐标。
- 绘制动画：`pathLength=1` + `stroke-dashoffset` 0.85s；数据点 0.28s 缩放淡入，按序 45ms 错开。

### 3.4 指标卡翻转（v0.1 的错误已修）

结构：`button.mcard > span.mcard-inner > (span.mface.front + span.mface.back)`。

```css
.mcard{height:194px;perspective:1200px}
.mcard-inner{height:100%;transform-style:preserve-3d;transition:transform .62s cubic-bezier(.2,.72,.2,1)}
.mcard[aria-pressed=true] .mcard-inner{transform:rotateY(180deg)}
.mface{position:absolute;inset:0;backface-visibility:hidden}
.mface.back{transform:rotateY(180deg)}
```

- 卡片**固定高度**，正反面绝对定位叠放，翻转不产生任何布局位移。
- 每张卡的翻转状态存于 `Set`，点一张不影响其他卡；只切换 class 与 `aria-pressed`，不重渲染。
- 正面：分类、名称、最新值、较前次变化（中性色 + 箭头）、记录次数、日期与来源。背面：最近 N 次迷你折线（基线 + 首末日期 + 末值），并注明"仅回顾已核对记录"。
- `aria-label` 同时描述正反面信息；正反面内容 `aria-hidden`，避免读屏重复。
- 原生 button，Enter/Space 可翻转；`prefers-reduced-motion` 下过渡降到 0.01ms，内容立即切换。

## 4. 术后恢复与上肢照护

### 4.1 术后恢复

- 阶段由用户选择（术后 0–2 周 / 2–6 周 / 3 个月以上），不按日期推断；切换后只改话题卡，不改任何数据。
- 每阶段三张话题卡（不是固定四类），**标题统一用「上肢」，不用「肩」**（D15）：

| 阶段 | 话题卡 |
| --- | --- |
| 0–2 周 | 伤口与引流 / **患侧上肢的"不做"清单** / 皮肤与患肢保护 |
| 2–6 周 | **术后上肢：活动与肿胀** / 伤口与瘢痕 / 体力恢复 |
| 3 个月以上 | 上肢围度 / 症状与功能 / 长期随访 |

- 每张卡只写"记录什么 / 该问什么 / 什么情况联系团队"，**不给动作、组数、负荷处方**。
- 引流记录：日期、mL、性状、备注；明确"正常范围由手术团队说明"。
- 已存康复建议：带来源、日期、"待专业复核"状态，与产品文案分开；标题里的"患侧上肢"同样不写成"肩"。

### 4.2 上肢与淋巴水肿

- 顶部状态：最新最大差值、与上次的差、标尺（0–2.5cm，虚线 2cm 参考关注线）。
- 四点位：腕横纹、前臂中段、肘上 10cm、腋下 10cm；健患侧成对输入，自动算差值并取最大。
- 趋势图：面积 + 折线 + 2cm 参考虚线；只画同协议记录。
- 记录表：显示各点位差值，不显示原始两侧值（详情可回源）。≤600px 时六列改为可换行、单位移到表头，**不靠横向滚动藏列**。
- 症状与功能：0–3 自评 + 描述；不做评分、不做因果归因。
- 红色提示：突然明显肿胀、发红发热、抬臂受限、皮肤破损 → "联系治疗团队"，并注明不是急诊分诊规则。
- 护理要点：抽血/输液/测血压、皮肤防护；压力袖套与手法引流明确"由专科个体化给出"。
- 顶部动作区有「记一句我的看法 →」，进入就诊准备的看法区（见 4.3）。

### 4.3 我的看法与担心（D16）

就诊准备页顶部固定一张卡：

- 标题「我的看法与担心」，右上角常驻标签「不是医生结论」。
- 副文案："只作为一条信息保留，方便你说明；不进入趋势、不写进摘要的事实区，也不参与任何判断。"
- 列出已记条目，每条带日期、记录人（本人/照护者）、固定尾注"这是一条看法，不是医生结论"。
- 底部输入框「记一句我的看法」+ 保存；留空不发请求。
- 诊断与处置的表述主语只能是治疗团队，本卡不得出现"可能/提示/建议"类判定。

问题清单表单同时区分两类：

| 类型 | 复选 | 显示 | 导出分区 |
| --- | --- | --- | --- |
| 想问的事 | 默认 | 无额外标签 | 一、想问的事 |
| 我的看法 / 担心 | 可选 | `我的看法 · 不是医生结论` 灰标 | 二、我的看法与担心（带引用块声明） |

导出 Markdown 固定顺序：`一、想问的事` → `二、我的看法与担心`（首行 `> 以下是我的看法与担心，**不是医生结论**`）→ 附上肢测量摘要 → 口径说明。

## 5. 设置面板（v0.3 新增）

入口在顶栏「设置」，弹窗内三个 tab：**工作区 / 文档解析 / 临床数据库**。不新增一级导航——配置不该占用一级注意力。

| 分区 | 必须出现的内容 | 交互约束 |
| --- | --- | --- |
| 工作区 | 资料根的**绝对路径**、更改位置、原件/派生/数据库三项占用、上次备份时间、立即备份、从备份恢复 | 拒绝根目录、用户主目录、桌面根；拒绝时给可读原因。恢复需二次确认并列出被覆盖范围 |
| 文档解析 | MinerU（默认）说明、云端隐私勾选、Token 掩码与替换、4 步注册引导 + 外链、模型默认 pipeline（接口拒参数才回退 vlm）、不做 Flash 降级（2026-10-22 决定） | 未勾选前不上传；Token 只能校验不能回显；保存先校验，失败分 401/429/网络 |
| 临床数据库 | 状态、最后检查时间、导入离线库、检查更新 | 未接入不阻塞其它模块；检查失败如实显示"未联网"，不假装已更新 |

三条硬规则：

1. **默认值必须写清后果。** MinerU 是云端处理，勾选框文案直说"会把你选的文件传上去"，不默认勾。
2. **不能回显的凭据就不给"查看"。** 只显示后 4 位，替换靠重新输入。
3. **路径错误不能静默。** 选到主目录、根目录或不可写位置时，明确说"已拒绝"和原因。

### 顶栏两个就绪状态（D27）

顶栏右侧两个 chip，回答的是「现在能不能开始工作」，不是业务统计：

| chip | 有值 | 空态 | 点击 |
| --- | --- | --- | --- |
| 资料目录 | `已激活` + 粉点，`title` 给绝对路径 | `未设置` + 灰点 | 有值 → 设置·工作区；空 → 目录选择器 |
| 对话 | `进行中` + 粉点 | `未进入激活` + 灰点 | 有值 → 会话归属；空 → 建会话 |

「资料整理进度」「当前关注阶段」**不占这两个位置**：进度写进「资料很多，帮我理清楚」入口的副标题，阶段用页头「当前阶段：X」按钮。旧的装饰 chip「模拟资料目录 / 会话未接入」已删除。

### 5.6 面板布局：customFrame + 业务区默认 0.65（D21 → D34 → 2026-10-19 修订）

宿主面板参数写死在这几行，M5 的 `cordis.patch.yml`、构建注入与界面判定都从这里取，**不在别处再写一份**（代码侧 `lib/layout.js` 与 `test/layout.test.mjs` 同值）：

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `customFrame` | `true` | **2026-10-19 从 `false` 改过来**：标准分栏下面板不能拖宽、不能收起（宿主服务没有这类接口，见下），而用户要求 AI 对话框可调 |
| `businessSide` | `left` | 业务在左、原生会话在右，与 SPEC §8 一致 |
| `businessWidth` | `0.65` | 宿主注册时仍校验 0.25–0.7；customFrame 下它记的是**默认业务区宽度**，与 `AGENT_PANE.default = 0.35` 互补 |
| `AGENT_PANE` | 默认 0.35，可拖 0.25–0.45，步进 0.02 | 由我们实现的拖动/键盘调整区间，取 starter `20-AGENT-PANE-DESIGN` 基线 |

**为什么改（源码级理由，证据见 `docs/AGENT-PANE-DESIGN.md` §0）**：标准分栏时宿主把 `--workbench-business-width` 写成注册时的静态值，服务只暴露 `register/isActive/ownsSession/add/open/home/ensureSession/currentSession` 等，**没有** `setBusinessWidth` / `togglePane`，DOM 里也不存在 splitter 节点——"关闭与拖宽用宿主原生面板自带能力"这条前提不成立。customFrame 下宿主把原生会话节点作为 `conversation` prop 交给我们排版，拖宽、收起/重开、宽度记忆才可能实现。代价是无会话态要自己引导（§6），且根节点首个子元素必须是 `<header>` 并用 `--dsh-frame-leading-clearance` 避让窗口按钮——都已在 `src/client.js` 里处理。

业务区默认仍是 **65%**，所以下面的 34 视图实测结论继续有效。

**实测（2026-10-17，chrome-headless-shell 131，macOS）**：

| 视口宽 | 相当于 | 侧栏 | 内容列 | 页面级横向溢出 |
| --- | --- | --- | --- | --- |
| 1440 | 全屏基线 | 236 | 1144 | 0 / 34 视图 |
| 1040 | — | 236 | 744 | 0 / 34 视图 |
| 936 | 1440 × 0.65 | 236 | 640 | 0 / 34 视图 |
| 900 | — | 折成整宽 | 868 | 0 / 34 视图 |
| 832 | 1280 × 0.65 | 折成整宽 | 800 | 0 / 34 视图 |
| 780 | 1200 × 0.65 | 折成整宽 | 748 | 0 / 34 视图 |

- 统计口径：8 个一级页 × 二级视图共 **34 个视图**，每档宽度逐视图 `documentElement.scrollWidth` 与 `clientWidth` 比对，差值 > 1 即算溢出。
- **负向对照**：向 `main` 注入 2000px 宽元素后 `scrollWidth` 变 2266 并被检出，移除后回到 936——证明"0 溢出"不是检测失灵。
- 只有 ≤900 才把侧栏折成整宽；936（最贴近真实的 65% 分栏）仍保留 236 侧栏，这也是最容易出问题的宽度。

**一处真实拥挤与规则**：936 下 `.grid.two` 两列各 313px，而「测量记录」六列表（日期 / 腕横纹 / 前臂中段 / 肘上 10cm / 腋下 10cm / 最大差）的 min-content 是 **417px** → 卡内要横向滚动 146px，而 `.card` 是 `overflow:visible`，滚动条被裁在卡外，实际表现为"最后两列看不见也没提示"。

规则：**该卡在 `.grid.two` 里默认整行**（`grid-column: 1 / -1`），不按断点分支。实测 936 下整行后卡宽 640、`scrollWidth === clientWidth`；1280 下卡宽 443 也放得下 417。理由：任何宽度下六列表被压到 313 都不该发生，加一次容器查询只是把同一结论写复杂。

**遗留（M2 补，不算已通过）**：≤900 时 `.pick`（16 项指标）折叠成 31px 摘要，只有"最多 4 个 · 已选 3"一行，没有展开指示；选中项变化时也不回显是哪几个。M2 要给摘要加展开箭头与已选指标名。

**对 V3 判定的影响**：改用 customFrame 后，官方 §8 的「`customFrame` 内不越界」**从"不适用"变回适用**——拖动、抽屉、弹层都必须在宿主主内容区内，且原生 `conversation` 节点可用。这一项只能装机实机验，本节的宽度实测不能替代它；「面板不遮挡侧栏/市场入口、键盘可达」同理。

## 6. 无障碍与响应式

- 跳转链接、`main[tabindex=-1]`、原生 button、`role=tablist` 二级导航、`aria-pressed` 翻转态、dialog 原生焦点管理、Escape 关闭。
- 触控目标 ≥44px（次要文字链 32px）。
- 断点：≤1180 两栏折叠、≤900 单列 + 指标选择折叠 + 图表横向滚动（`min-width:620px`）。
- **≤900 不得隐藏两个就绪状态 chip**：它们是功能入口（v0.3 曾按旧设计写 `.status{display:none}`，390 宽下两个入口直接消失，已修）。窄屏只缩字号到 10.5px 并允许顶栏换行，「资料目录」「对话」两个标签必须保留。
- `prefers-reduced-motion` 关闭绘制与翻转过渡。

## 8. 与闸口的关系（D18）

- UI-DESIGN 描述的界面，是 **G2** 的审查对象；G2 只认"用户逐页确认的范围与交互"，不认截图与脚本。
- 界面里任何"需要存下来"的东西，都要能在 SCHEMA-SPEC 找到对应实体；找不到就说明模型缺东西，回到 **G3** 补模型，而不是在界面里造一个假字段。
- 界面里任何"只是当场状态"的东西（折叠、选中、缩放、当前 Tab），**不得**要求入库。

## 9. 已知取舍

- 图表按各指标自身范围归一化，无法直接比较不同指标绝对值；这是为了同屏回顾，不是数值对照工具。
- 2cm 参考线只作提示，阈值与测量规范待专业核验，未写成诊断标准。
- 术后恢复不给动作处方，因此页面偏"记录 + 提问"；如需康复动作，必须接入治疗师审核内容，不能在原型里先写。
- 症状轨道目前按月取最大强度，是演示级聚合；真实版本应按事件显示并支持回源。

## 10. 开发版（v0.4.0）的界面实现与实测

界面不是新画的一版：`public/style.css` 以 `prototypes/v0.3/style.css` 为底，只在末尾追加开发版需要的规则（`.setup`、`.import-box`、`.cand-table`、`.stepper`、`.seg`、`.kv`、`.banner`、`.tabs-mini` 等）。原型仍是视觉基准，开发版不"顺手优化"文案。
