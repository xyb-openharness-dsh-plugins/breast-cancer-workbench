## 2. 三个必答问题（这是 G3 的全部）

### ① 用户的"看法/担心"能不能带结论？

| | |
| --- | --- |
| 现状 | `viewpoint.is_conclusion` 被 `CHECK (is_conclusion = 0)` 钉死，永远只能是 0；看法不进曲线、不算差值、不进摘要事实区，导出时单独一节，标题固定「以下是我的看法与担心，不是医生结论」 |
| 为什么问 | 这是产品立场的落地点（D16）。一旦允许 1，工作台就在替医生下判断 |
| 选项 | **A 保持恒 0（建议）**；B 允许用户标"我认为这是结论"，但仅作文字标签、不进任何计算 |
| 选 B 的代价 | 要改 CHECK 约束 + 改导出分区 + 在界面上永远解释不清"你的结论"和"医生结论"的区别 |
| 我的建议 | **A**。用户想表达判断，写到 `question`（"想问医生"）或 `viewpoint.text` 里即可，不新增语义 |

### ② 四点位臂围必须四个点一起记吗？

| | |
| --- | --- |
| 现状 | `arm_set` 1 条 + `measurement` 4 条（腕横纹 / 前臂中段 / 肘上 10cm / 腋下 10cm，患侧健侧各一轮），`set_id` 外键成组；**缺健侧时只存患侧绝对值，不生成 `derived_diff_num` 差值** |
| 为什么问 | 真实场景里用户常常只量一侧或漏一个点。强制 4 点会让"记不下来"变成"不记" |
| 选项 | **A 允许 1–4 点，缺什么就少什么，差值只在同组同点位患健齐全时算（建议）**；B 必须 4 点齐全才能保存 |
| 选 B 的代价 | 移动端录入成本翻倍；历史数据出现"记了一半"时无法保存，只能丢弃 |
| 我的建议 | **A**。图上缺点的位置留空，不插值、不补 0 |

### ③ 记录写错了，是改还是新增一版？

| | |
| --- | --- |
| 现状 | **新增**一条 `record`，`supersedes_id` 指向旧记录、`version+1`，旧行 `status='superseded'`；派生视图只取"未被取代的最新版本"；禁止 `UPDATE` 历史值 |
| 为什么问 | 这决定"导出过的报告会不会变"和"能不能追溯当时为什么这么记" |
| 选项 | **A 新增版本、旧值留痕（建议）**；B 原地覆盖（表更简单，但导出过的摘要会对不上账） |
| 选 B 的代价 | 无法回答"上个月给医生看的那版写的是什么"；`export_job.stale_at` 也就失去意义 |
| 我的建议 | **A**。代价只是每条记录多存几行，换来可回溯 |

> 除这三问外，**没有第四个需要拍板的结构问题**。§5 的五个已知未定都不阻塞 M1。

## 4. 六条硬约束（改表前先过这六条）

1. **事实四层不合并**：原件 → 候选 → 记录 → 指标值，跨层只允许上层指下层。
2. **可比性跟方法走**：检验看 `lab_method`、测量看 `protocol_id`；不满足就断线，不硬连。
3. **未检测 ≠ 阴性 ≠ 未知**：三态文案与字段一一对应，不合并显示。
4. **看法不是结论**：`is_conclusion` 恒 0，且不进任何派生计算。
5. **更正不覆盖**：只新增版本，`UPDATE` 历史值是禁止项。
6. **界面状态不入库**：折叠、Tab、缩放、排序留客户端；唯一例外是用户声明的阶段。
