# 指南与工作台的融合方案（讨论稿 v0.1）

日期：2026-10-21，2026-10-22 更新。状态：**G1 已落地（v0.10.0）、G2 已落地（v0.11.0）、G3 的 CTCAE 一侧已落地（v0.12.0）**；G3 的双标准并列与 G4 未实现。指南原件已入 [`guidebooks/`](../guidebooks/README.md)（G0 完成），本文只解决"怎么长在一起"。

一句话判断：**工作台缺的不是"库里有一份指南"，而是把指南变成三把刻度尺——"何时查"（节奏）、"对谁适用"（人群）、"多严重"（分级），并且给每条刻度标回页码。** 第四样东西指南里有、但产品不能拿：处置推荐。

---

## 1. 现状盘点：已经具备的挂靠点

| 已有 | 位置 | 正好能接什么 |
|---|---|---|
| 版本化指标定义（code/单位/可比性/显示形态） | `MetricDefinition`，`docs/SCHEMA.md` §2.1 | 接指南的"随访检查项目"清单，一个检查项 = 一个指标或一类检查 |
| 治疗事件带 `setting / regimenCode / cycleNo / planVsActual` | `TreatmentEvent` §2.5 | 接"适用人群"判定：在用什么药，决定指南哪条适用于你 |
| CTCAE 分级（只覆盖 anc/hgb/plt/wbc） | `dsh/ctcae.js` + `assets/reference/ctcae/` | 接指南第 10 章 11 类不良反应分级，扩展口径 |
| 来源定位 `sourceDocumentId / sourceLocator` | `Observation` / `Measurement` | 扩成"指南出处"（文档 id + 页码 + 表号） |
| `SymptomEntry` 0–3 自报 | §2.4 | 接指南明确推荐的 **ePRO**（P209 注 a：病史采集建议用电子化患者报告结局） |
| "参考关注线"机制（臂围 2cm 先例） | `docs/BREAST-DOMAIN.md` §3.6 | 接 LVEF 下降、CTRCD 阈值的"画线不判定" |
| 待办 / 问题 / 看法 三个用例实体 | 用例层 | 接"下次复查窗口" → 变成问题或自己安排的待办 |

结论：**不需要为指南新建一套体系**，需要的是在既有四层边界里，把"指南"作为一等来源加进去，并守住"出处不是结论"。

## 2. 指南里能对上的，其实是四种颗粒

| 颗粒 | 指南里的样子 | 例子（页码） | 能不能进产品 | 进哪一层 |
|---|---|---|---|---|
| **结构** | 分型、分期、路径分支 | 分子分型 P36；AJCC 8 版 TNM P35；MBC 治疗原则 P167 | 能，但只做"你属于哪条分支"的标签，不选方案 | 适用层 |
| **节奏** | 时间间隔 | 术后 2 年内每 3 个月、3–5 年每 6 个月、>5 年每年（P208 表 9.5）；乳腺 X 线每 12 个月、心超每 3 个月（P209 表 9.6） | 能，且这是用户价值最大的一块 | 节奏层 |
| **阈值/分级** | 数值边界 | CDK4/6 中性粒 1 级 <LLN–1.5、2 级 1.5–1.0、3 级 1.0–0.5、4 级 <0.5（P227）；肝损 1 级 1–3×ULN…4 级 >20×ULN（P227）；QTc 450–480 / 481–500 / ≥501ms（P227） | 能，但必须与 CTCAE v5.0 双轨并列 | 分级层 |
| **处置** | "推荐/建议/应" | G-CSF 一级预防（P218）；Hb≤100 启用 ESA（P219）；PLT≤10 预防性输注（P220）；LVEF 降 ≥16% 暂停治疗至少 4 周（P223） | **不能**转成产品语句 | 禁止层（只做折叠原文） |

这张表是整份方案的地基：**同一份 PDF 里四类颗粒必须分开处理**。把它们一起塞进"知识库检索"，产品就一定会说出"你应该……"。

## 3. 四层设计

### L1 出处层：每条引用都能回到"哪一版、第几页、哪张表"

- 数据：`guideline_document`（id / org / version / published / sha256 / pages）+ `guideline_ref`（documentId / section / page / tableId / quote ≤200 字）。
- 挂靠：`Observation / Measurement / SymptomEntry / TreatmentEvent / Task` 增加 `guidelineRefIds[]`（**多对多，不覆盖已有来源**）。
- 界面固定两段式，中间不合成判断：

  > 指南这里写的是：术后 2 年内每 3 个月随访 1 次。（CACA-CBCS 2025 精要本 · P208 表 9.5）
  > 你的记录是：最近一次复诊 2026-07-12。

- 红线：引用块**永远不写成段落结论**；不出现"所以""因此""你需要"。
- 验收：随便点开一张指标卡背面的"出处"，能落到具体页；页码与 sha256 对得上 `manifest.json`。

### L2 适用层：指南"对谁适用"，用记录算出来，不用问卷问出来

- 派生一组布尔标签（纯函数，不落事实）：`on_ai`、`on_lhrh`、`on_serm`、`on_anthracycline_or_trastuzumab`、`on_ici`、`on_bisphosphonate`、`on_cdk46`、`post_menopause`、`bct`（保乳）、`axillary_dissection`、`stage_iii_plus`。
- 来源：`TreatmentEvent.regimenCode` + 病理字段 + 术式，全部已有；算不出来的（如绝经状态）不出标签，界面显示"未记录"。
- 用途只三件：① 决定随访清单显示哪几行；② 决定指标卡"为什么这条与你有关"；③ 决定节奏表取通用行还是分期变体行。
- 文案纪律：写「记录里有 AI 用药，指南这一条适用于使用 AI 的人」，**不写**"你属于高危人群"。

### L3 节奏层：把"什么时候该查"变成可核对的窗口，不是催办

- 结构化数据：`guidebooks/derived/cadence-2025.json`（单一来源，带 sha256 与页码），每行 = { 项目, 适用标签, 间隔或窗口, 变体条件, ref }。
- 从 P208/P209 能直接落 12 行：常规（病史/体检/超声/实验室/乳腺 X 线）、特殊（胸部 CT、妇科超声、骨密度、骨扫描、脑 MRI、心超+心电图+心肌酶、尿常规+甲功+肾上腺、乳腺 MRI、PET-CT）。
- 派生 `dueWindow(tag, lastRecord)` → 三行并置：

  > 指南节奏：术后 2 年内每 3 个月（P208）
  > 你最近一次：2026-07-12 乳腺超声
  > 参考窗口：2026-10 前后 · 以你的医生安排为准

- 分期变体（0 期 / pT1micN0 / 部分 I 期可放宽到 2 年内每 6 个月，P208 注 b）：**只有用户声明了分期才套用**；未声明时显示通用节奏 + "未按分期调整"。
- 出口：窗口可一键变「想问医生的问题」或「我自己安排的待办」。**不发通知、不弹提醒、不写"该复查了"**。
- 验收：把术后时间改到 3.5 年，窗口从 3 个月变 6 个月；删掉治疗记录后，心超行消失（而非变成"不需要"）。

### L4 分级层：中国口径与 CTCAE 双轨，不合并、不取严

- 现状 `dsh/ctcae.js` 覆盖 10 个 code：血液学四项（绝对阈值）+ `alt`/`ast`/`alp`/`tbil`/`cr`（×ULN，须带化验单参考上限）+ `qtc`（绝对 ms，最高 3 级）。这是 v0.12.0 补的。指南还能补的是**口径不同**那几项：`neutrophil`（CDK4/6 用本实验室 LLN，CTCAE 用固定 2.0）、`diarrhea`（次/日）、`ild`（症状型）。
- 关键冲突（必须显式处理，不能糊）：

  | 指标 | CTCAE v5.0（现用） | CACA-CBCS 2025 | 差异性质 |
  |---|---|---|---|
  | 中性粒 1 级 | <2.0–≥1.5 | <LLN–1.5（P227） | 起点不同：CTCAE 用固定 2.0，指南用本实验室下限 |
  | 血小板 | <125 起 1 级 | CTIT 定义 <100，干预分层 10/75/100（P220） | 一个是分级，一个是干预阈值，**不是一回事** |
  | 血红蛋白 | <120 起 1 级 | CRA 关注线 Hb≤110 或降幅≥20g/L（P219） | 同上 |
  | LVEF | CTCAE 分级 + 无症状下降 | CTRCD：绝对降 ≥16%，或 <LLN 且较基线降 ≥10%，暂停 ≥4 周（P223） | 指南给的是**处置阈值**，不是分级 |

- 我的建议：`gradeStandard: 'ctcae5' | 'cbcs2025'` 并存，**卡片正面仍只显示 CTCAE 一个徽章**（避免界面变成对照表），背面第二行给指南口径 + 页码；当两者级差 ≥1 时，背面加一句"两套口径在这一条上不一致，见 P227"，**不自动取严**。取严＝替医生做判断。
- "参考关注线"不升级为分级：LVEF 的 16%/10%、臂围的 2cm 都只画虚线 + "指南/文献关注点，不是诊断线"。
- 症状型（腹泻、恶心、乏力、ILD）指南按"日常生活活动受限"描述，不是数值 → 只做 0–3 自报 + 原文折叠对照，不做数值分级。

### X 禁止层：处置推荐怎么"看得见但不生效"

- 允许：折叠块「指南原文（P223）」+ 短摘录 ≤200 字 + 页码。
- 不允许：把"暂停治疗至少 4 周""推荐 G-CSF 一级预防""Hb≤100 用 ESA"改写成陈述句、要点列表、清单勾选项、Agent 回答的主句。
- 文案红线扩词：`应该 / 必须 / 建议复查 / 需要治疗 / 暂停用药 / 可以考虑加用`——在 guideline 语境下一律拦截（现 `check-wording` 已有机制，加规则即可）。

## 5. 五处冲突与我的取舍

1. **双标准并列会让界面变重。** 取舍：正面一个徽章（CTCAE），背面一行指南口径；不一致时只标"不一致"，不解释谁对。
2. **指南的分层（骨折风险低/中/高危，P205）本质是风险评分，而项目红线是"不做风险评分"。** 取舍：不实现分层计算，只展示 T 值 + 原文分层表；因此 `docs/BREAST-DOMAIN.md` 的"不做风险评分"继续有效。
3. **臂围 2cm/10% 在 2025 指南里没有数值阈值**（9.1 只写"定期评估、淋巴水肿门诊随访"）。取舍：现有参考线保留但改标注为"文献常用口径，中国指南未给数值"，并把 `BREAST-DOMAIN.md` 待核验清单第 1 项标为"已查：指南未给阈值"。
4. **OCR 风险。** 精要本是 MinerU 输出，表格偶有串行。取舍：任何进代码的阈值必须人工回 PDF 核对，提交信息写明核对了哪页；未核对的只做展示、不做计算。
5. **版权。** 精要本页脚"违者必究"。取舍：`guidebooks/` 不进 `package.json` 的 `files`（已验证 `npm pack` 不含），仓库 private，界面只出元信息 + ≤200 字摘录。

## 7. 分期（每步都能停）

- **G0（已做）**：`guidebooks/` 原件 + `manifest.json` + 索引与使用边界。
- **G1 出处层（已做，v0.10.0）**：`assets/reference/guideline/refs.json`（只有页码 + ≤200 字摘录，随包分发）+ `dsh/guideline.js`（`guidelineRef` / `cbcsView` / `refLabel`）；指标卡背面并列一行、指标检测页折叠表格。**没有建表**："指标 → 指南条目"是静态映射，纯函数即可，等 G4 需要记录"某条记录被谁引用"时再建 `guideline_ref`。
- **G2 节奏层（已做，v0.11.0）**：`assets/reference/guideline/cadence.json`（表 9.5 三段 + 表 9.6 十五项 + 7 条药名规则）+ `dsh/cadence.js`（`checkpoints` / `treatmentTags` / `applicableChecks` / `buildFollowupPlan`）；指标检测页「随访节奏」卡四行式，节点可转问题/待办、**不发提醒**。**没有建表**：节奏是静态间隔 + 手术日期算出来的日历格，落库只会多一份会过期的副本。
- **G3 分级层（一半已做，v0.12.0）**：CTCAE 一侧扩了 6 个 code——`alt` / `ast` / `alp` / `tbil` / `cr` 走「×ULN，必须用这张化验单的参考上限，没有就返回 `needsUln`」；`qtc` 走绝对 ms、最高 3 级。字典 18 → 22 项，单测 222 → 231。**未做**的是双标准并列（`gradeStandard: 'ctcae5' | 'cbcs2025'`、两套口径差 ≥1 级时的背面提示），所以本文上面那张冲突表还没有落到界面。
- **G4 适用层 + Agent 检索**：标签驱动 + `agent-context.js` 挂指南检索，回答必带 refId，无命中就说"指南里没这段"。

## 8. 不做

- 不做"指南推荐方案"生成、不做治疗路径推荐、不做预后/复发风险计算。
- 不把 CSCO 的分层推荐（I/II/III 级）做成产品菜单。
- 不把指南当知识库喂给 Agent 自由作答；只做"检索 → 引用 → 原文"。
- 不在界面出现"指南建议你"这种句式；主语只能是"指南这一条写的是"。
