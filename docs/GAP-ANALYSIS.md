# 设计文档与原型对比检查 v0.1

日期：2026-10-17。检查人：接手 Agent（Codex 之后）。范围：`docs/` 全部文档、`prototypes/v0.1`、参考项目 `xyb-workbench@0.1.27`（只读）。用户反馈三条：乳腺癌专属场景未覆盖、一图秀动态与多指标缺失、指标卡片翻转做成上下展开。

本文件是对照记录，不是验收结论；结论分级见文末。

## 1. 三个硬伤（均已复现，非主观印象）

| # | 现象 | 证据 | 根因 |
| --- | --- | --- | --- |
| H1 | 乳腺癌专属内容几乎为零 | `grep` 全仓：`淋巴`0、`水肿`0、`臂围`0、`内分泌`0、`骨密度`0、`LVEF`0、`放疗`0（`app.js` 与 `docs/` 均为 0） | 场景表 S1–S7 是**通用肿瘤工作台**场景，只换了癌种名；乳腺癌最耗时、最需要长期记录的两件事（术后上肢功能、淋巴水肿）没有进入场景、字段和原型 |
| H2 | 一图秀只有一张静态假曲线 | `app.js:40` `chart()` 固定 4 个点、单序列、无动画、无多选、无时间窗；`timelinePage()`（`:43`）把同一份 `metrics()` 又渲染一遍 | 一图秀被做成"页面拼贴"，没有独立的图表状态（选中指标、时间窗、缩放、治疗节点、悬停/固定点） |
| H3 | 指标卡点开是上下展开，不是翻转 | `:41` 卡片是 `<button class="metric-toggle">`，展开内容作为**兄弟节点**插到按钮下方；`:78` `metric()` 改 state 后整页 `render()` | 结构上不可能翻转：没有 3D 容器、没有正反面、没有 `backface-visibility`；整页重渲染还会杀掉任何过渡 |

参考实现（`lib/client.js:104-110`）用的是真正的 3D 翻转：

```css
.xyb-metric-card{perspective:1000px;overflow:hidden}
.xyb-metric-inner{transform-style:preserve-3d;transition:transform .68s cubic-bezier(.2,.7,.2,1)}
.xyb-metric-card[aria-pressed=true] .xyb-metric-inner{transform:rotateY(180deg)}
.xyb-metric-face{position:absolute;inset:0;backface-visibility:hidden}
.xyb-metric-back{transform:rotateY(180deg)}
```

关键不是动效参数，而是**卡片高度不变、正反面叠放、状态互不干扰**（`flippedMetrics` 按指标 code 独立记录）。v0.1 三点全错。

## 2. 一图秀能力对照

| 能力 | xyb-workbench 0.1.27 | 小粉宝 v0.1 | 判定 |
| --- | --- | --- | --- |
| 多指标同图 | 左侧指标复选，最多 6 色序列 | 无，单张白细胞 | 缺 |
| 时间范围 | 近3月/6月/12月/全部 | 只有"全部/近期"两档，且按月份字符串前缀硬判 | 缺 |
| 缩放 | 25–100% range 滑杆 | 无 | 缺 |
| 治疗节点叠加 | 虚线 + 标签（每个化疗周期一条） | 底部一行文字 chip，不在图上 | 缺 |
| 关键点/大变化标注 | 首末点 + ≥20% 变化标记 | 无 | 缺 |
| 点选追溯到来源 | 点→详情行（指标/值/日期/来源） | 点→弹窗，只到"血常规报告示例" | 弱 |
| 指标卡翻转 | 真 3D 翻转，背面最近 5 次折线 + 首末日期 | 上下展开，背面只有文字 | 错 |
| 卡片分组 | 按类别（肿瘤标志物/血常规/肝肾/营养…） | 三张平铺（白细胞/体重/其他） | 缺 |
| 与治疗对照的免责 | 明写"各指标按自身范围绘制" | 仅一句"不代表疗效" | 弱 |
| 空/单点状态 | 至少两次才连线，明确提示 | 单点提示有，但只有体重一例 | 部分 |

结论：一图秀不是"再美化一点"的问题，是**功能模型缺席**。v0.2 必须补齐图表状态机，否则后续接入真实数据仍要重写。

## 3. 乳腺癌场景覆盖对照

按"患者实际会问、会记录、会带去复诊"的话题逐项检查。`现状` 指 v0.1 原型是否有可操作入口与字段。

| 话题 | 为什么必须覆盖 | 现状 | v0.2 处置 |
| --- | --- | --- | --- |
| 术后伤口/引流 | 出院后 1–2 周最具体的不确定 | 无 | 术后恢复页：引流量/伤口情况记录 + 何时联系团队 |
| 患侧上肢活动度 | 腋窝手术后肩关节受限常见，影响穿衣梳头 | 无（仅"上肢与日常活动"一句） | 肩前屈/外展记录，与臂围同轨 |
| 淋巴水肿测量 | 腋窝清扫+放疗后终身风险，靠围度趋势早发现 | 无 | 四点位双侧臂围、自动差值、趋势图、2cm 参考线（标注待专业确认） |
| 淋巴水肿症状 | 沉重/紧绷/肿胀先于 measurable 变化 | 无 | 0–3 症状自评 + 功能影响 |
| 皮肤与患肢保护 | 抽血/输液/测血压/防晒/蚊虫叮咬是日常决策 | 无 | 护理要点卡（标注来源与待复核） |
| 内分泌治疗副作用 | 5–10 年长期用药，关节痛/潮热直接影响依从 | 无 | 症状记录 + 与医生讨论的问题；不评价是否停药 |
| 骨健康 | AI 类药与骨丢失相关，需基线 DXA | 无 | T 值作为指标序列，只呈现记录 |
| 心脏毒性 | 蒽环类/曲妥珠需 LVEF 随访 | 无 | LVEF 指标序列 |
| 化疗骨髓抑制 | 白细胞/中性粒细胞是每次化疗前的门槛 | 只有白细胞 | 白细胞+中性粒细胞+血红蛋白+血小板 |
| 肿瘤标志物 | CA15-3/CEA 随访常用 | 无 | 独立分类，单点不连线 |
| 放疗皮肤反应 | 放疗期间高频问题 | 无 | 归入不适记录 + 术后/放疗期话题 |
| 生育与性健康 | 年轻患者核心议题，敏感 | 仅 FEATURE-REVIEW 一句 | 心理支持下的独立私密话题，默认不进入分享 |
| 复查节奏 | 术后 2 年 3–6 月一次，之后拉长 | "长期生活与随访"一句话 | 近期安排 + 复查资料归档；不生成复查方案 |

**判断**：v0.1 的八模块骨架可以留，但内容层是"胰腺癌/卵巢癌工作台换了名字"，没有回答"乳腺癌患者今天打开它要做什么"。这是设计文档层面的缺口，不是原型美化问题。

## 4. SPEC 评估

保留的部分：四层数据边界、处理状态与来源分离、计划/实际分离、来源回溯、私密内容默认不分享、低负担录入。这些是正确的，且比参考项目写得更严谨。

问题按严重度排序：

| 级别 | 问题 | 影响 |
| --- | --- | --- |
| 高 | 场景表（S1–S7）与模块表（八模块）没有一一映射，也没有"该场景需要哪些字段"的落点 | 开发时只能照抄参考界面，于是出现"有页面没内容" |
| 高 | 没有指标字典：哪些指标、什么单位、什么分类、单点是否连线、不同检测方法如何处理，全部未定 | 一图秀无法实现，也无法验收 |
| 高 | 乳腺癌领域模型缺术式/腋窝处理/放疗野/内分泌方案/HER2 状态等关键维度 | 淋巴水肿风险、心脏毒性、骨健康都无法关联到人 |
| 中 | "全病程"被写成阶段并列，但没有定义**阶段如何被用户确认**、阶段与任务卡的对应关系 | 看板只能做一个下拉框，阶段选择不影响任何内容 |
| 中 | 验收候选是句子，不是可执行断言（无输入、无预期、无失败条件） | "确认原型"没有客观依据 |
| 中 | AI 价值范围（D05）仍未决，却挡在场景细化前面 | 实际上不挡：可以先做"记录+回溯+提问"，AI 只做整理；应把它降级为二期开关 |
| 低 | 多份文档重复描述同一约束（BRIEF/DESIGN-PROMPT/DESIGN-SESSION/DESIGNER-BRIEF），版本漂移风险 | 维护成本；本轮起以 SPEC 为唯一权威 |

## 6. 结论分级

- **已复现**：H1–H3、一图秀 10 项能力缺失、14 个话题中 13 个无入口。依据是仓库内代码与文档检索，可复查。
- **设计判断（非事实）**：把"上肢与淋巴水肿"放在全程管理二级、而不是新增一级导航；理由是控制导航膨胀，同时用看板卡与一图秀轨道保证可见性。需用户确认。
- **未验证**：真实患者是否愿意做四点位测量（负担）、2cm 参考线在中国临床语境下的表述、压缩袖套等护理要点的本地指南依据。均标注"待专业核验"，不写成结论。
